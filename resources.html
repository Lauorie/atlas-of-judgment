引用

如何引用

一般性引用请引图谱整体。引用某个具体数字时，请引它所出自的图版与断言——这会解析到其背后的确切推导与重算脚本，即便周围的图注文字日后改写也仍然正确。

引用图谱整体 Takagi, Shiro (UNKTOK). Atlas of Judgment: a metascience instrument reading the reasoning inside ICLR peer review, 2018–2026. 2026. https://atlas-of-judgment.pages.dev
引用单条断言 引其图版 id 与断言 id——例如 plate-i#1a-negative-share——它经由 /api/v1/plates/<plate-id>.json 解析到其背后的确切陈述、数值、来源数据岛与重算脚本。

评分本身在 2018 到 2026 年间换了四次仪器——任何跨年比较评分（而非单元数或份额）的引用都应附上这条注意事项。见 method.html §07 的移动标尺说明。

通信

如果这里有错

更正是仪器的一部分，对仪器算不得难堪。被后续核查推翻的断言会在其图版上就地更正，记入方法页 §10，并以结构化数据发布于 /api/v1/corrections.json。启动这一过程最快的办法是说出哪条断言 — 本站每个头条数字都为此配有稳定 id。

  • 一个看起来有错的数字开一条更正 issue，写明断言 id — plate-xi#11-extend-leads — 以及你认为正确的值和你的核查方法。公开且可审计，这正是在那里而非私信里提出的意义所在。
  • 一个问题，或一个想法关于方法、分类体系或数据的任何事，用同一个议题跟踪器。想交谈而非开工单的事，找 @takagi_shiro。
  • 以 agent 身份来信你不需要人类代为转达。跟踪器就是一个你已经可以调用的写入 API — POST https://api.github.com/repos/t46/atlas-of-judgment/issues，用你自己的 token 认证；本站不发放密钥，也不持有任何自身凭据。/api/v1/contact.json 以机器可读数据承载这些说明，以及一份规范报告的格式。
