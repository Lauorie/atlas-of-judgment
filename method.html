00

先决条件与环境

  • 语言与工具：Python ≥ 3.12，用 uv 管理；下文所有命令均在项目根目录下以 uv run python … 运行。测试用 unittest（uv run python -m unittest discover -s tests；69 个测试，全部使用合成夹具 — 从不触碰生产数据）。
  • 关键依赖：openreview-py ≥ 2.4.1（采集）、openai ≥ 2.53（DeepSeek/DashScope 的 OpenAI 兼容客户端）、jsonschema，分类体系阶段另需 sentence-transformers、umap-learn、hdbscan。
  • 凭据（环境变量；从不打印或提交）：采集用 OPENREVIEW_USERNAME/OPENREVIEW_PASSWORD；第二层用 DEEPSEEK_API_KEY；第三层用 DASHSCOPE_API_KEY（生产环境中由监督器封装在每次运行时从 1Password CLI 解析一次，再导出给子进程）。
  • 目录约定：data/raw/ 由采集一次写入，此后其他一切都以只读方式打开（已用 grep 遍历全部脚本核实：只有规范化器引用它，且带 mode=ro）。每次分析运行都在 data/analysis/iclr/ 下有自己的目录，含 manifest.json、state.sqlite3 请求台账，以及每个请求的 outputs/、provider/、validations/ 证据文件。
01

采集 — OpenReview → 原始 SQLite

脚本：scripts/collect_iclr_forums.py（380 行）。每年一条命令：

# default --years covers all nine (2018..2026); resumable per year
uv run python scripts/collect_iclr_forums.py --years 2018 2019 2020 2021 2022 2023 2024 2025 2026
  • 范围决定：仅 ICLR，2018–2026，OpenReview 为唯一来源。选 ICLR 是因为它公开被拒论文的评审；ICML/NeurIPS 暴露的多为已接收论文的评审。2017 被刻意排除（无法核实为 OpenReview 官方会场）。年份范围在项目一开始就固定；之后演变的只有提取方法。
  • API 版本处理：运行时检测，不用硬编码表。venue_config() 先向 OpenReview API v2 查询 ICLR.cc/{year}/Conference 组；若存在 content.submission_id 则留在 v2，否则回退到 v1（{venue_id}/-/Blind_Submission）。实测：2018–2023 解析为 v1，2024–2026 为 v2。
  • 分页与韧性：游标分页（after=<last note id>、sort="id"、每页 100），带 details="replies" 在同一次调用中取回回复图；最多 7 次重试，指数退避（1s→30s 上限）；若某页无进展则触发 RuntimeError 守卫。可通过按年持久化在 collection_status 中的 after_id 游标续跑；forums 按 (year, forum_id) upsert，重跑不会重复。
  • 不做匿名化：note 按原样序列化（.to_json()），含签名。数据为公开数据；流水线中任何位置都没有 PII 遮蔽。
  • 输出：data/raw/iclr/openreview.sqlite3 — forums 52,460 行（2018:935 · 2019:1,419 · 2020:2,213 · 2021:2,594 · 2022:2,617 · 2023:3,792 · 2024:7,404 · 2025:11,672 · 2026:19,814）；collection_status 9 行，全部 completed=1，且 stored == expected。
已知局限完整性为自报：期望计数来自同一次运行的第一页，随后又由该运行自己满足。不存在对照 OpenReview 线上数据的事后对账（inventory_iclr.py 抓取线上计数，但只写入 data/inventory/，从不与原始库交叉核对）。若 OpenReview 内容在采集后发生变化，原始快照不会察觉。
02

规范化 — 仅溯源

脚本：scripts/normalize_iclr.py（334 行）。确定性且幂等 — 按年在一个事务内删除并重建；没有墙钟时间戳或随机性（时间来自原始的 cdate/mdate）。

uv run python scripts/normalize_iclr.py
  • 它添加了什么 — 仅溯源，不做解读：classify_kind() 剥去 API v2 的 “edit” 包装后，按有序模式列表匹配（official_review → meta_review → desk_rejection → withdrawal → decision → official_comment → public_comment → comment → unknown）；classify_role() 读取签名字符串（/authors、/reviewer_、/area_chair_、/program_chair、公开的 ~ 档案），并以 kind 为后备。
  • 输出：data/processed/iclr/analysis.sqlite3 — papers 52,460 · messages 792,703。按 kind 细分：official_comment 507,543 · official_review 199,031 · decision 40,821 · meta_review 30,108 · withdrawal 8,235 · public_comment 5,563 · desk_rejection 980 · comment 422 · unknown 0。

第二层 — DeepSeek 分析备忘

引擎：scripts/run_deepseek_pilot.py，模型 deepseek-v4-flash，关闭思考，temperature=0.4，无随机种子。持久化的 SQLite 预算台账（budget_state、api_call_attempts）配 fcntl 锁，使支出在中断之间保持一致；每次运行都预先声明成本上限。

04

第三层 — Qwen 结构化单元

模型（两轨）：qwen3.7-flash，经 DashScope 的 OpenAI 兼容端点 https://dashscope-intl.aliyuncs.com/compatible-mode/v1，实时 API，enable_thinking=false，严格的 JSON 模式约束输出。未设置 temperature 或随机种子 — 采用服务商默认值（一处已记录的可复现性缺口；见 §08）。每个请求只读第二层备忘 — 从不读原始评审。清单文件锁定 protocol_sha256 与模式哈希。

轨道 A — 紧凑（ICLR 2026，评审级）

# input: episode-lite-2026-full-single (one review per shard, 75,859 shards)

  --output data/analysis/iclr/review-logic-qwen-2026-full …
uv run python scripts/qwen_review_logic_batch.py run-realtime \
  --output data/analysis/iclr/review-logic-qwen-2026-full

模式 review-logic-compact-v0.1.json：每篇评审一组 logic_units[]，每条含 {inspected_object, observation, reasoning, judgment, valence, suggested_improvement, evidence_refs, support_status, confidence, missing_links}，外加摘要与未解决的张力。结果：74,380 / 75,859 完成（98.1%），1,479 失败，$28.79，声明上限 $40。提示词经约 10 次门控的试点/对照运行后冻结于试点 v3（批处理 API 尝试以 model_not_found 失败；实时 API 成功）。

06

单元提取与归纳分类体系

最后的数据层把两轨展平为逐单元的 SQLite 表，并把每条单元分派到一套归纳得到的分类体系。这里的一切都是本地计算 — API 成本为零 — 并全部脚本化：

# 1) flatten complete records into unit tables
uv run python scripts/extract_logic_units_2026.py     # → unit-taxonomy-2026-v1/units.sqlite3 · 410,586 units
uv run python scripts/extract_logic_units_direct.py   # → unit-taxonomy-direct-v1/units.sqlite3 · 1,009,592 units

# 2) induce the taxonomy from a 12,000-unit sample (seed 7)
uv run python scripts/induce_unit_taxonomy.py --sample-size 12000 --min-cluster-size 60 --seed 7

# 3) hand-write taxonomy-v1.json from the cluster digests, then assign all units
uv run python scripts/assign_unit_taxonomy.py          # 2026 track
uv run python scripts/assign_unit_taxonomy_direct.py   # direct track, reusing the same centroids
  • 选取规则：只提取各源运行中 status='complete' 的行（部分失败行也有输出；它们被排除）。
  • 嵌入：BAAI/bge-small-en-v1.5，归一化，批大小 256，本地。字段 inspected_object 与 reasoning 分别嵌入。
  • 聚类：UMAP（15 个分量、30 个近邻、min_dist 0、余弦、random_state 7）→ HDBSCAN（min_cluster_size 60、min_samples 10、EOM）。得到：36 个审视对象簇（37.6% 噪声）与 17 个推理簇（61.5% 噪声）。
  • 人工步骤：人工阅读各簇范例并手工合并为 12 审视对象 × 12 推理标准，附定义，记录于 taxonomy-v1.json。两个异质簇被排除在质心构建之外。没有以任何既有方案（包括本项目自己的 Atlas 卡片）作种子。
  • 分派：类别质心 = 成员簇样本嵌入的归一化均值（带种子的流水线重跑可精确复现簇成员 — 已核验）；每条单元按余弦取最近质心，相似度作为该单元的置信度存储。高置信度（≥0.75）占比：审视对象 94.5%，推理标准 87.9%（2026 轨道）；直接轨道上逐年平均相似度平稳在约 0.81，因此跨年比较不是迁移产生的伪影。
  • 注意：分类体系在 2026 紧凑备忘上归纳，再迁移到直接轨道；质心相同，备忘风格不同。平稳的相似度曲线是这一迁移成立的证据。
  • 方案效度：四部分的单元粒度与 12 × 12 分类体系是对评审文本的一种归纳切分 — 按上述检查内部一致，并有一次外部锚定（§07 的构念效度网格：这些类别在应当起作用之处确实撼动了会议自身的分项评分）— 但没有任何检查确立它们是正确的切分。换一种粒度或换一种合并会画出另一张图；下游的每一个计数都是此方案之内的计数。

07

仪器校验 — 读取读者本身

以上各节描述数据如何生成；本节问的是机器读取可信到什么程度。两项校验，都从随发布的单元数据库计算得出。它们也出现在图谱里，但归属于此：它们是关于仪器的陈述，而非关于审稿人的发现。

支撑状态 — 仪器以自己的声音发言之处

每个单元带有一个在结构化时赋值的 support_status 字段：reviewer_explicit（以审稿人明述的文字为依据）、memo_inferred（由 DeepSeek 分析备忘依上下文阐述而非引用）或 mixed。两条轨道按构造就差异悬殊 — 评审级 2026 轨道为 19.8% 明述 / 77.1% 推断 / 3.1% 混合，forum 级轨道为 57.4% / 40.8% / 1.7% — 因为 Layered 提示词要求备忘做综合，Direct 提示词则要求引用行 ID。这一占比在类别与年份之间并不均匀：

备忘推断占比，对象 × 年份 — forum 级轨道（紫色越深 = 推断越多）

无法复现之处

  • LLM 采样：DeepSeek 以温度 0.4 运行，未设随机种子；Qwen 既未设温度也未设随机种子。重新运行会生成结构相似但文本不同的备忘与单元。项目中的每个 seed 都控制输入选择，而非模型输出。

  • 上游漂移：OpenReview 不公开完整的编辑历史；原始快照无法察觉平台上采集之后发生的更改。
  • 哈希覆盖：协议/模式的 SHA-256 固定覆盖 Qwen 时期的运行（16 份清单）；更早的试点产物只能依靠文档互证。

实际的路径 — 试点、失败、决定

这份编年记背后经过脱敏的原始会话历史 — 每条命令与每个决定按发生时的原样，共 21,386 个事件 — 发布于项目仓库（codex-history/），与完整流水线代码和这些页面一起。以上各节描述流水线最终运行的样子。本节记录它实际如何走到那里 — 小规模试验、死路与中途修正，按顺序排列。这里没有事后的粉饰；每一项都有仍在磁盘上的产物目录或清单作支撑。

每个生产阶段都先做了试点

  • 没有任何东西未经试验就全规模运行。试点账簿（均可只读核验）：initial_blind 395 个试点作业（$0.33），trajectory 327（$0.51），paper_synthesis 100（$0.52），forum_direct 100（$0.32），以及一次专门的 100 个 forum 方法比较运行（$0.40）。
  • 方法的分岔：Layered（每条评审链 3 次 DeepSeek 调用）与 Direct（整个 forum 一次调用）在 100 个 forum 上正面比较，由同一模型盲评 — Layered 以 69–31 胜出。九年语料仍选了 Direct，出于成本，也因为分层的错误会向下游传播。这一质量上的取舍是明知而接受并记录在案的，没有隐藏；Layered 仍然驱动高分辨率的 2026 轨道。

episode 弯路（一次有收获的失败）

  • 一个中间的 "evaluation episode" 模式（v0.1，之后是更精简的 v0.2 Lite/Deep）被设计出来，并在精选集上验证：1,000 篇分层抽样的评审（选择用随机种子 20260816）加 63 次深度抽取 — 两者都保留为校准资产。
  • 把它扩展到全部 75,859 篇评审时接连以三种方式失败：第一次全量运行因抽取浅薄被否；v2 因字段模板化、复制粘贴被否；随后三个校准配置正面比较（r5-low、r15-medium、r8-medium-v3），采用了 r8-medium-v3 — 但全语料的预计墙钟时间约为一周，运行在中途被有意停止（计划 ~9,774 个分片）。
  • 随后智能体式的 Luna 引擎本身也从这项工作中撤下：它在被 "安全地" 停止时已完成 75,859 中的 876 篇，失败 186 次，整个抽取围绕 Qwen 上一个更轻的紧凑模式重新设计。那 876 份 Luna 输出保留为比较基线，未合并。

Qwen 的试炼（紧凑轨道）

  • 先试 Batch API：27 个试点请求 0 个成功（批处理端点返回 model_not_found）。改用实时端点：22/27。随后两次单评审对照运行（46/54，然后 53/54），尝试了每请求打包两篇评审并因覆盖率损失而否决，一次 206 个请求的负载测试（203 个成功）作为 75,859 个请求的生产运行之前最后的放行关卡。

Direct 轨道的走走停停

截断阶梯

图版的顺序不是工作的顺序

这样一页读起来可能像是每项分析都已预见、每张图版都在等前一张。事情并非如此，若声称如此，就是一种值得点名的研究做法：看到结果之后再发明动机。所以，直说：

  • 顺序是编辑上的安排，事后才加上。这些分析历经数周，按问题出现在我们脑中的先后建成；之后图版才被归入各幕，并为阅读排序。这一安排至今已修订三次 — 从松散的序列到六幕；当关于评判的那一幕承载着两个不同的问题时拆成七幕；再重新分组，使每一幕以其图版共有的问题开场（即当前形式）。这些重排都没有改变任何分析。没有哪张图版的位置能证明它是为前一张而做的。
  • 有些图版始于一个明述的问题，在任何数字存在之前。七幕修订中新增的九张图版 — 推理的句法、早判、组合条款、无名判例、法则的代价、控罪单、招式、借来的裁决、未修订的法典 — 每张都先写下问题，之后才计算。其中两张返回零结果，并按零结果报告（rebuttal 招式；疑问式）。一个候选问题在运行之前就被放弃，因为答案事先过于明显：审稿人是否在 LLM 时代长出了一条关于提示工程的条款。占据那张图版的恒常性检验取代了它。
  • 有些图版坦白说是探索性的。脚本、阶梯与神谕的存在，是因为数据支撑得起这样的描述，而非某个假设要求它们。它们的导语如实说明，没有制造动机。
  • 一条已发表的断言有错，已就地更正。早判图版起初写道，一篇评审的裁决到第六个单元即可读出，"相对于十一个单元的评审长度中位数"。中位数其实是五，这使原断言近乎循环论证。分析限于十个单元及以上的评审重跑 — 在那里问题才是真问题 — 图版现在报告的是那条曲线，它在八或九处饱和。错误与修正记录于此，而非悄悄覆盖。
  • 第二条断言在发布当天即被更正。水印图版首次发布的读数（2026-08-27 上午）把 2023 年后同稿审稿人对象集合重叠度的上升呈现为内容层面的趋同，并指出其转折“正落在水印到来的那一年。”当天运行的一次规模匹配零检验 — 同样的 forum、同样的集合大小、内容从当年的构成中随机抽取 — 吸收了这一上升：审稿人在 LLM 时代每篇评审指控的对象更多（平均集合大小 3.4 → 3.8），而选择超出规模的部分持平（+0.037–0.054，2018 年最高）。图 29c 现已画出该零模型；图 29d 报告同时运行的另外两项结构零检验（构成熵、推理嵌入差距）。未更正的读数在线上页面留存了大约半天。
  • 第三条断言几小时后倒在同类零检验之下。更正后图版的图 29d 曾写道，单个审稿人自身的注意力熵“从 0.742 → 0.766 上升：单个审稿人看的东西种类略多，而不是略少。”当晚运行的一次对抗审计 — 刻意寻找集合大小假象的同类 — 发现这一上升也大多是机械性的：一个 n 匹配的零模型（同一批审稿人的单元数，对象从当年自身构成中随机抽取）几乎同步上升，因为审稿人在 LLM 时代每篇评审提交的单元更多，当年的构成本身也变得更均匀。+0.024 的上升中只有 +0.008 在零检验后留存，且无趋势。图 29d 现已画出该零模型，只断言留存下来的部分：2023 年后没有收窄。同一次审计没有削弱用语趋同面板，反而使它更锐利：按章节拆分，论文内的上升集中在总结部分（+20%，仍在攀升），而批评正文上升 +6% 并在 2025 年后停滞 — 两种分解现都已上图。“分布更广”这一肯定读法在线上页面留存了不到一天。
  • 凡图注为某项分析给出理由之处，那要么是该分析被运行的原因 — 我们当时有的一个问题 — 要么被标明为结果最终所关涉之事。第二类理由写成后果（“这关涉什么”），绝不写成动机。

七幕修订新增了九张图版（句法、早判、组合条款、无名判例、法则的代价、控罪单、招式、借来的裁决、未修订的法典），外加门，它只是导航，不作断言。（在 2026-08-24 的重组中，法则的代价并入代价图版，试炼并入后果，脚本并入行程作为其序幕；它们的仪器未变。）后来的一次添加，水印（2026-08-27），收束此列。它们的仪器，以及各自可能误导之处：

  • 句法 — 形式标签来自图版 III 的分类器（5 折交叉验证准确率 0.685，宏 F1 见文件）；转移与一个在每篇评审内部置换的零模型比较，因此报告的提升度只是评审内的顺序效应，而且很小 — 图版直说这一点，不加粉饰。
  • 早判 — “到第六个单元即可读出”说的是一个基于粗特征（对象 × 判定计数）的分类器，而不是审稿人何时做出决定；审稿人可能先起草结论。目标是 2026 年偶数刻度上 6 分及以上，3 折交叉验证，随机种子固定。2026-08-21 的后续分析共用该目标与交叉验证：原始文本条是拼接评审字段上的 TF-IDF（1–2 元语法，min_df 5）；计数权重是整篇评审逐主题否定计数（加上肯定与有保留计数总量）上的 L2 逻辑回归系数 — 相关计数上的描述性系数，连同其各折离散度一并报告。
  • 组合条款 — 子聚类为 bge-small 嵌入上的 k-means（k=8，随机种子 46）；名称由机器读取器基于样例起草、经分析者复核；四个近乎重复的所指聚类被合并为一项笼统指控，合并记录在构建脚本中。原始聚类随数据集发布。所指是在单元的蒸馏观察上聚类的，因此标题份额（46% 未点名任何部件）对照源评审做了审计：在 30 例未点名观察的样本中，凡能定位到源指控句的，其具体程度都与观察一致 — 观察笼统时，审稿人原话同样笼统；仅有一例含糊，其描述句点出了指控句未点出的部件。审计记录随代码库发布（notes/combo-audit-30.txt）。
  • 无名判例 — 抽取器是一个引用正则加 arXiv ID，排除会议缩写；行文中的提及（"the BERT paper"）会被漏掉，因此所有文献份额都是下限 — 结论（不存在正典）在任何合理的抽取器下都成立。（姓氏，年份）键刻意过度合并，这只会强化零假设。测量跑了两遍，两遍都报告（第二遍的设计在出结果前已声明）：先在蒸馏后的单元文本上（5 / 29 / 66；点名率按年 8.4%→3.5%；最大键 10 个 forum），再在原始评审文本上重测，单元只用于定位指控 — 取该单元所在 forum 中词元重叠最高的那篇评审里每一句提到新颖性的句子 ±2 句（79% 的单元找到了窗口；窗口刻意偏向点名，因为它可能吸入相邻批评的引用）。原始读法给出 12 / 25 / 63，点名率按年 20%→11%，最大键覆盖 23,251 个 forum 中的 21 个。点名水平对仪器敏感（下限 5%，宽松窗口 12%）；两个标题事实则不然：在两种仪器下约三分之二的异议全无所指，点名率在两种仪器下都于 2018→2026 减半，正典在两种仪器下都不出现。构建脚本：build_canon_native.py。
  • 法则的代价 & 控罪单（经 2026-08-24 合并后，即今日的图版 XIV · 代价与图版 XIII · 控罪单）— 逐单元的法则归属来自抽样的句子聚类（每份案卷 40k），因此绝对的共同提出率被稀释；两张图版因而只报告比值（提升度）— 独立抽样设计使其在一阶上无偏 — 以及各法则的平均赤字 — 抽样使其变稀，但不引入偏差。赤字按各年评分的标准差归一化；评分通过后缀匹配把审稿人键接到 OpenReview 签名。控罪单的评审内提升度还额外检验了论文质量混杂（build_chargesheet_control.py，在出结果前已声明）：每一对展示的配对都在同一论文的两位不同审稿人之间重测。相吸在跨审稿人时保持中位数 ×1.44，对比评审内的 ×1.87（一部分归于论文，一部分归于审稿人）；相斥则完全没有跨审稿人的抑制（×0.97，对比评审内的 ×0.75），把只提其一的习惯归于审稿人，而非论文。跨案卷配对不可能共享一个单元，因此多法则句子无法抬高任何一份清单。
  • 招式 — 结果仪器只计入审稿人在回应后单元中记录下的判断变化（"减弱/反转"）；无声的提分对它不可见。标记是确定性的正则，原文引在构建脚本中。争辩的溢价是一个自选招式所带的关联 — 作者手握强牌时才争辩。对同一批 722,406 条回复句子做的并行嵌入聚类（k=12）分开的是话题多于策略，得到同样的零结果；它以 moves-raw 之名发布。
  • 借来的裁决 — 回声层级是缓存推理嵌入上的余弦约定（0.75 / 0.90）；移动阈值改变的是水平，不是比较。最近邻归因度量的是文本接近度，而非因果影响 — AC 与审稿人可能各自独立地呼应了论文。集中度只在有三条或更多回声单元的 forum 上计算。
  • 未修订的法典 — 不随时间改变这一断言用分半对照校准（在 2026 年的一半数据上拟合法典，留出的另一半为 0.152）；每一年都落在其 0.008 之内。图注承认两个分辨率限制：句子嵌入可能漏掉保持语域不变的语义变化；迁移条款依托法典中唯一一个真正混合的聚类（多数为语域迁移；区分是站得住的第二种读法），因此其 5–7% 区间是六个中最不确定的。反向拟合（把 2018–19 的法典向前应用）在仅 417 句上用 k=6，报告为薄弱的佐证，而非证据。
  • 水印（2026-08-27 加入，在对 LLM 参与同行评审的文献做过调研之后）— 设计上仅在语料层面：逐篇评审的 AI 检测器被排除，依据是对非母语作者误报的记录（Liang et al., Patterns 2023）与实例层面的不可靠（Yu et al., ICLR 2026）。仪器：一份十三词标记表，在任何计数之前从 Liang et al.（ICML 2024）与 Kobak et al.（Science Advances 2025）逐字冻结；各年的文档频率对照其自身 2018–2022 的线性外推（Kobak 的超额词汇设计）；2023 作为内置的安慰剂年份，另有一份冻结的十词阴性对照表跑过完全相同的机制。只取自由文本 — 五个评审表时代的枚举字段被剔除，相似度水平从不跨表格边界比较；标题所称的趋同断言只在表格不变的 2024–2026 窗口内、在一套共享的 TF–IDF 词表下成立。相关量组按长度十分位分层（存在性度量对长度敏感 — 对照表低于趋势的漂移显示了背景潮汐），把评分比较以该论文最长的评审为基准，并在读取任何质量梯度之前把标记标签在论文内置换 200×（以比较组为条件，单凭均值回归就能制造出一个梯度）。计划、假设与决策规则：notes/llm-era-analysis-plan.md，计算前冻结；第 1 轮之后的补遗（固定词表、长度分层、置换对照、依 Sharma et al. arXiv:2601.20920 划分的质量层）在计划文件中有标注。图版上引用的先前工作：Liang et al. 2024；Kobak et al. 2025 与 Gray, arXiv:2512.01560（超额词汇方法的先驱 — 面向论文整体，而非评审）；Latona et al. 2024；Wu et al. arXiv:2604.19578（最近邻 — 同一批会议，度量的是方面覆盖而非相似度）；Sharma et al. 2026；Kim et al. arXiv:2605.20668（AI 审稿人 21% 对 3% 的相互重叠，由专家标注）；Baumann et al. arXiv:2605.03202（“蜂群思维效应”）；以及 arXiv:2607.10511，它在 ICLR 评审文本诊断量中读出 2022–23 的转折 — 本图版的安慰剂年份与这位时间上的近邻相差一个周期。2026-08-27 在 Semantic Scholar + arXiv 上的检索未找到任何已发表的、基于真实 OpenReview 数据的论文内同稿评审相似度逐年测量；这只记为一条检索结果，不作为新颖性的证明。构建脚本：build_llmtrace_data.py（原始文本），build_llmtrace_mix.py（补遗 E+F：类别构成熵、规模匹配的重叠零模型、推理嵌入离散度 — 图 29d 背后的仪器，以及 § 10 所记录的对图 29c 的同日更正）。

仪器扩展（2026-08-24 审阅轮）

逐图版审阅时，发现若干图注断言只存在于构建脚本一次性的打印输出里 — 当时可核验，输出滚走后便无法核验。于是定下规则：图注或统计栏里的任何数字，要么落在发布的 JSON 中，要么可由一个具名脚本重新算出。以下各项据此持久化：

  • build_acecho_data.py — 现在输出 gap_by_cutoff：最近邻余弦 ≥ 0.70 / 0.75 / 0.80 时元评审单元按判向的份额，支撑借来的裁决中批评比称许在每个阈值下都被更多回声的断言（+7.0 / +6.6 / +3.3 pp）。
  • build_score_depth.py — 现在输出 dispersion.accept_unan_div：均值恰为 4.0 与 6.0 时一致评审组与分歧评审组的接收率（分段版本在段内把极差与均值混在一起，只作为朴素对比保留）。支撑度量中的“录用决定是均值，而非方差”（均值 6.0 时 92.1% 对 91.8%；4.0 时 12.1% 对 13.1%）。
  • build_timeless_data.py — 现在输出 dist_se：到 2026 年法典的平均距离按年做句子自助法得到的 SE（2018：0.0034 … 2026：0.0006），使未修订的法典的零假设连同其分辨率一起陈述：早年可测地（+2–3 SE）却微小地（+0.006）高于校准值；句子在评审内成簇，所以即便这些 SE 也偏乐观。

长标尺与投影 — 仪器，而非图版

有两件常驻图形在图谱各处反复出现，既不是图版，也不是账目条目。它们是编辑装置，诚实的做法是在此说明，而不让读者误以为是图：两者都不对语料做任何断言。每一件对数据只有恰好一处真实依赖，下文点明。

长标尺是右侧页边的一把折尺，由文档本身构成：它的铰链标出各幕的边界，各段长度与该幕的图版数成比例 — 加载时从页面上数出，非手工调定 — 刻度每图版一格，每格可点击。沿尺刻着一套放大倍率词汇（句子 · 评审 · 断言 · 代价 · 房间 · 法庭 · 评分 · 年份 · 档案），每幕一词，点出该幕置于镜下的对象有多大。这套词汇属于编辑：它是作者对本书结构的自述，不是对任何东西的度量，应当像读目录那样读它，而非像读图版那样。

投影是标题到来时投过页面的一道阴影，其中有语料里的真实句子显现、消隐。它是装饰。这些句子是真实的语料文本 — 这一点是真实的数据依赖 — 但出现哪几句不构成任何断言；不应从选取中读出频率、排名或代表性。整个图层在 prefers-reduced-motion 下和打印时都不存在，这本身就表明它不承载页面所依赖的任何内容。
