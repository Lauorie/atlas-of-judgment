评判图谱 · Atlas of Judgment

机读接口

一个静态、零成本的 API，建在图版所依据的同一份已审计数据之上。每个端点都是 CDN 上的一个纯 JSON 文件 — 一个来源，两种格式：供人阅读的页面，以及供机器引用、重算与审计的断言。

1,420,178 个审稿人逻辑单元 · 410,586 个为 2026 年全深度读取 · 九年 ICLR · 人可读的图谱 ↗
快速开始
三件仪器
01 · 索引
GET /atlas-of-judgment/api/v1/index.json

目录：每张图版、每个数据岛、每个端点，以及哪些岛供给哪些图版。

02 · 存证
GET /atlas-of-judgment/api/v1/plates/plate-i.json

一张图版的证词：其头条断言，每条附带带类型的值、来源岛、推导、重算脚本与所适用的告诫。

{
  "id": "1a-negative-share",
  "statement": "71.8% of all units end negative, and no object escapes …",
  "value": { "quantity": 0.718, "unit": "share_of_units", "n": 410586 },
  "source_island": "viz-data.json",
  "derivation": "sum(n where verdict=='negative') / sum(n) …",
  "recompute": "scripts/build_unit_viz_data.py",
  "verified": "D10 number audit, 2026-08-24",
  "caveat_refs": ["unit-recall-bias"]
}
03 · 数据岛
GET /atlas-of-judgment/api/v1/data/viz-data.json

54 个底层数据岛，以独立文件提供 — 与人读页面中嵌入的 JSON 逐字节相同的孪生体。每个岛在索引中的条目都带有所服务文件的 sha256，重算因此能证明自己起于同一份字节。

04 · 更正记录
GET /atlas-of-judgment/api/v1/corrections.json

更正台账：每一条发布后被发现有误的断言，已在图版上原地更正并记入方法 §10 — 此处以结构化条目呈现（发布时的断言、核查所示、更正后的读数、错误存续的时长，以及指向存证与岛键的链接）。

约定
如何读一条断言
来源、推导与已核验三者之别
本站几乎每一个头条数字都是对一个数组（多为 triples[]）计算出的聚合量，而非单个 JSON 叶节点。因此一条断言把来源（哪个文件、哪个数组）、推导（算法，直白写明）与已核验（重算过它的、带日期的人工审计）分开陈述。一个装得比这更精确的指针，只会更不诚实。
告诫附着于断言，而非页面
每条断言都列出 caveat_refs — 空列表本身就是一条断言：无一适用。全语料范围内须知的一条：ICLR 在 2018–2026 年间四次更改评分量表与评审表单，因此任何跨年比较评分的断言都带有移动标尺告诫（见方法 §07「移动的标尺」）。关于单元计数与占比的断言 — 本站大部分内容 — 由分类体系度量，那才是恒定的仪器。
引用方式
请引用图版 id + 断言 id，例如 plate-i#1a-negative-share — 视觉改版后依然稳定，即便数字周围的文字被重写。衍生数据采用 CC BY 4.0 许可；底层评审经由 OpenReview 归其匿名作者所有。
